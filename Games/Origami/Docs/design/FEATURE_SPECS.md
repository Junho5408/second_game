## 공통 표기 (수용 기준용)

- 명령: `NewRun` 새 런 · `Start(m)` 작품 m 접기 시작 · `In(x)` 동작 x 입력(x ∈ U/D/L/R/F) · `Hint` 힌트 · `Abandon` 포기 · `EndDay` 하루 마치기.
- `Make(m)` = `Start(m)` 후 m의 정답 순서(`CONTENT_SPECS.md`)를 실수·힌트 없이 모두 입력(→ ★3 완성).
- `Waste(m)` = `Start(m)` 후 즉시 `Abandon`.
- 별도 언급이 없으면 모든 시나리오는 `NewRun` 직후(1일차, 돈 20)에서 시작한다.
- "거부(사유)"는 명령이 거부되고 상태가 전혀 바뀌지 않음을 뜻한다(R-015).
- 모든 기능은 R-001에 따라 시계·난수를 쓰지 않는다. 테스트는 Unity 없이 명령 열만으로 재현할 수 있어야 한다(F-001~F-006).

### F-001 런 진행 (시작 · 하루 · 종료 · 파산)
- 목적: 7일짜리 한 판의 뼈대(시작 상태, 하루 넘기기, 완주/파산 종료)를 제공한다.
- 관련 규칙: R-001, R-002, R-003, R-012(일차 진행 부분), R-013, R-015
- 기대 동작:
  1. `NewRun` → R-002 시작 상태.
  2. `EndDay` → 정산(F-005) 후 1~6일차면 다음 날(시도 5로 초기화) + 파산 검사, 7일차면 완주 종료.
  3. 새 날 시작 시 돈 0이면 파산 종료. 종료 시 엔딩 판정(F-006).
  4. 종료 후에는 `NewRun` 외의 모든 명령이 거부(RunEnded)된다.
- 엣지 케이스:
  - 아무것도 하지 않고 `EndDay`만 반복 → 7일 완주, 돈 20 → E-01.
  - 접는 중 `EndDay` → 거부(FoldInProgress).
  - 낮 동안 돈 0이 되어도 파산이 아니다(오늘 작품이 저녁에 팔릴 수 있음).
  - 7일차 정산 후에는 파산 검사 없이 완주 종료(일차 7 유지, 8일차 없음).
  - 런 도중 `NewRun` → 진행 중 접기·오늘 작품 폐기, 엔딩 판정 없음.
- 수용 기준:
  - AC-01: `NewRun` 직후 상태는 일차 1, 돈 20, 남은 시도 5, 해금 {plane, boat}, 잠김 {frog, crane, dragon}, 모든 작품 완성 수 0, 실패 수 0, 오늘 작품 0개, 접는 중 아님, 런 종료 아님이다.
  - AC-02: `EndDay` 1회 후 일차 2, 돈 20, 남은 시도 5, 런 종료 아님이다.
  - AC-03: `EndDay` 7회 후 런 종료, 종료 사유 완주, 일차 7, 돈 20, 엔딩 E-01이다. 이어서 `EndDay`와 `Start(plane)`은 각각 거부(RunEnded)되고 일차·돈이 변하지 않는다.
  - AC-04: `Start(plane)` 후 `EndDay`는 거부(FoldInProgress)되며 일차 1, 남은 시도 4, 접는 중 상태가 유지된다.
  - AC-05: `Waste(plane)` 5회 후 `Start(plane)`은 거부(NoAttemptsLeft)되고 돈 15다. 이어서 `EndDay` 후 일차 2, 남은 시도 5다.
  - AC-06 (파산): 1~4일차에 매일 `Waste(plane)` 5회 + `EndDay`를 하면 4번째 `EndDay` 직후 런 종료, 종료 사유 파산, 일차 5, 돈 0, 실패 수 20, 엔딩 E-01이다.
  - AC-07 (낮 동안 돈 0은 파산 아님): 1~3일차 매일 `Waste(plane)` 5회 + `EndDay`(4일차 시작 돈 5) → 4일차 `Make(boat)` 3회(돈 2) → `Waste(plane)`(돈 1) → `Make(plane)`(돈 0, 런 종료 아님) → `EndDay`. 4일차 인기 작품은 boat이므로 boat ★3 = 13, plane ★3 = 6, 판매액 13×3 + 6 = 45. `EndDay` 후 돈 45, 일차 5, 런 종료 아님이다.
  - AC-08 (완주 시 돈 ≤ 20): 1~3일차 매일 `Waste(plane)` 5회 + `EndDay`(돈 5) → 4~7일차 `EndDay`만 → 런 종료, 종료 사유 완주(파산 아님), 돈 5, 엔딩 E-01이다.
  - AC-09: 2일차에 `Start(boat)` 후 `NewRun`을 하면 상태가 AC-01과 같다.
  - AC-10 (결정성): 같은 명령 열(예: AC-07 전체)을 새 런 두 개에 각각 적용하면 일차, 돈, 남은 시도, 해금, 작품별·등급별 완성 수, 실패 수, 종료 여부, 엔딩이 모두 같다.
- 범위 밖: 저장/불러오기, 일수 변경 옵션.

### F-002 접기 시작 (종이 구매)
- 목적: 작품을 골라 종이값을 지불하고 접기를 시작한다. 돈·시도·해금이 선택을 제약한다.
- 관련 규칙: R-004, R-015
- 기대 동작: 조건을 통과하면 돈 −종이값, 남은 시도 −1, 접는 중(진행 단계 0, 실수 0, 힌트 0). 실패하면 R-004 순서의 첫 사유로 거부.
- 엣지 케이스:
  - 돈 = 종이값 → 허용, 돈 0.
  - 여러 사유가 동시에 해당 → R-004 순서상 처음 사유만 보고(예: 접는 중이면서 잠긴 작품 → FoldInProgress).
  - 존재하지 않는 작품 ID(빈 문자열 포함) → UnknownModel.
  - 접기 시작 시점에는 판매가가 정해지지 않는다(완성 등급·판매일에 따라 결정).
- 수용 기준:
  - AC-01: `Start(boat)` 후 돈 19, 남은 시도 4, 접는 중, 작품 boat, 진행 단계 0/4, 실수 0, 힌트 0이다.
  - AC-02: `Start(frog)`는 거부(Locked), 돈 20, 남은 시도 5다.
  - AC-03: `Start("unicorn")`과 `Start("")`은 각각 거부(UnknownModel)다.
  - AC-04: `Start(boat)` 후 `Start(frog)`는 거부(FoldInProgress)다(잠김보다 우선).
  - AC-05: `Waste(plane)` 5회 후 `Start(frog)`는 거부(Locked), `Start(plane)`은 거부(NoAttemptsLeft)다.
  - AC-06 (돈 부족): 1~3일차 매일 `Waste(plane)` 5회 + `EndDay` → 4일차 `Make(boat)` 3회(돈 2, frog 해금) → `Waste(plane)`(돈 1) → `Start(frog)`는 거부(NotEnoughMoney), 돈 1, 남은 시도 1이다. 이어서 `Start(plane)`은 허용되어 돈 0, 남은 시도 0이다.
  - AC-07: 어떤 명령 열에서도 돈은 0 미만이 되지 않는다(AC-06 이후 `Abandon`, `Start(plane)` → 거부(NoAttemptsLeft), 돈 0 유지).
- 범위 밖: 종이 미리 사두기(재고), 종이 종류 선택, 환불.

### F-003 접기 입력 (단계 · 실수 · 힌트 · 망침 · 포기 · 등급)
- 목적: 도안을 외워 순서대로 접는 핵심 조작과 품질 판정을 제공한다.
- 관련 규칙: R-005, R-006, R-007, R-008, R-009, R-015
- 기대 동작:
  1. 정답 입력 → 진행 +1, 마지막 단계면 완성(오늘 작품에 (작품, 등급) 추가, 완성 수 +1, 해금 검사).
  2. 오답 → 실수 +1(같은 단계 유지), 실수 3 → 망침(실패 수 +1, 작품 없음).
  3. `Hint` → 현재 단계 정답 공개, 단계당 1회만 셈.
  4. `Abandon` → 망침과 같은 결과.
  5. 등급: 벌점 = 실수×2 + 힌트 → ★3(0) / ★2(1~2) / ★1(3+).
  6. 접는 동안 조회 가능한 정보: 작품, 진행 단계/전체 단계, 맞힌 단계 기호, 실수 수, 힌트 수, 현재 단계 힌트 공개 여부(공개 시 기호), 현재 벌점 기준 예상 등급.
- 엣지 케이스:
  - 실수 2에서 마지막 단계 정답 → 망치지 않고 ★1 완성.
  - 같은 단계에서 `Hint` 반복 → 힌트 수 1만 증가.
  - 힌트 공개 후 오답 → 실수 +1, 힌트는 계속 공개 상태.
  - 접는 중이 아닐 때 `In`/`Hint`/`Abandon` → 거부(NoFold), 런 종료 후 → 거부(RunEnded).
  - 진행 단계 0에서 `Abandon` → 허용(종이값 손해).
  - 완성·망침·포기 후 바로 다음 `In`은 거부(NoFold)(남은 입력이 다음 접기로 넘어가지 않음).
- 수용 기준:
  - AC-01: `Start(boat)`, `In(D)`, `In(U)`, `In(F)`, `In(U)` → 접는 중 아님, 오늘 작품 [boat ★3], boat ★3 완성 수 1, 돈 19(판매 전)이다.
  - AC-02: `Start(boat)`, `In(D)` 후 진행 단계 1/4, 맞힌 기호 [D]다.
  - AC-03: `Start(boat)`, `In(L)` → 실수 1, 진행 단계 0. 이어서 D, U, F, U → [boat ★2](벌점 2).
  - AC-04: `Start(boat)`, D, L, U, R, F, U → 실수 2, [boat ★1](벌점 4), 망침 아님.
  - AC-05: `Start(boat)`, L, L, L → 망침: 접는 중 아님, 실패 수 1, 오늘 작품 0개, boat 완성 수 0, 돈 19, 남은 시도 4.
  - AC-06: `Start(boat)`, D, L, U, R, F, L → 3번째 실수에서 망침(진행 단계 3이었음), 실패 수 1, 작품 없음.
  - AC-07: `Start(boat)`, `Hint` → 공개 기호 D, 힌트 1. `Hint` 다시 → 힌트 1 유지. `In(D)` → 다음 단계는 공개 안 됨. `Hint` → 공개 기호 U, 힌트 2. U, F, U → [boat ★2].
  - AC-08: `Start(plane)`, `Hint`, U, `Hint`, L, `Hint`, R → 힌트 3, [plane ★1].
  - AC-09: `Start(plane)`, `Hint`, `In(D)`(오답), U, L, R → 실수 1, 힌트 1, 벌점 3, [plane ★1].
  - AC-10: `Start(plane)`, `Hint`, `In(D)` 후 공개 기호는 여전히 U, 실수 1이다.
  - AC-11: `Start(plane)`, `Abandon` → 접는 중 아님, 실패 수 1, 돈 19, 남은 시도 4.
  - AC-12: 새 런에서 `In(U)`, `Hint`, `Abandon`은 각각 거부(NoFold)다. `Make(plane)` 직후 `In(U)`도 거부(NoFold)다.
  - AC-13: 접는 중 예상 등급은 실수 0·힌트 0이면 ★3, `Hint` 1회 후 ★2, 이어서 오답 1회 후 ★1이다.
  - AC-14: 5종 작품 각각 `Make(m)` 시(해금 후) CONTENT_SPECS 정답 순서대로 입력하면 ★3으로 완성되고, 정답 순서의 단계 수는 plane 3, boat 4, frog 6, crane 8, dragon 10이다.
- 범위 밖: 제한 시간, 연속 성공 보너스, 되돌리기(undo), 도안 일부만 보기.

### F-004 작품 해금
- 목적: 쉬운 작품을 반복해 어려운 작품을 여는 런 내 성장.
- 관련 규칙: R-010
- 기대 동작: 선행 작품 누적 완성 수(등급 무관)가 3에 도달하는 즉시 다음 작품 해금(boat → frog → crane → dragon). 런이 끝나거나 새 런까지 유지.
- 엣지 케이스: 망침·포기 미포함, ★1도 포함, 여러 날에 걸친 누적 포함, plane은 해금에 무관, 인기 작품 표와 무관.
- 수용 기준:
  - AC-01: `Make(boat)` 3회 직후(같은 날) frog 해금, 바로 `Start(frog)` 허용.
  - AC-02: `Make(boat)` 2회 + `Waste(boat)` 1회 → frog 잠김.
  - AC-03: 1일차 `Make(boat)`, `EndDay`, 2일차 `Make(boat)`, `EndDay`, 3일차 `Make(boat)` → frog 해금(일차를 넘어 누적).
  - AC-04: boat를 모두 ★1로 3회 완성(매번 서로 다른 3개 단계에서 `Hint` 사용, 벌점 3)해도 frog 해금.
  - AC-05: `Make(plane)` 5회 → frog 잠김.
  - AC-06: frog 3회 완성 → crane 해금, crane 3회 완성 → dragon 해금(F-006 AC-10 시나리오 2일차에서 확인).
  - AC-07: 해금 후 `NewRun` → 해금 {plane, boat}로 돌아간다.
- 범위 밖: 돈으로 해금 사기, 런 간 해금 유지.

### F-005 판매 · 하루 정산
- 목적: 접은 작품을 돈으로 바꾸고, 등급과 인기 작품으로 가격 차이를 만든다.
- 관련 규칙: R-011, R-012
- 기대 동작: `EndDay` 시 오늘 작품 전부를 `floor(기본가 × 등급PCT × 수요PCT / 10000)`로 판매, 합계를 돈에 더하고 목록을 비운다. 정산 내역(작품별 가격, 합계, 정산 후 돈)을 조회할 수 있다. 누적 기록: 총 판매액, 총 종이값.
- 엣지 케이스:
  - 오늘 작품 0개 → 합계 0.
  - 수요는 판매하는 날(= 완성한 날) 기준. 작품은 다음 날로 넘어가지 않는다.
  - 인기 작품이 잠겨 있어도 표 그대로.
  - `NewRun`으로 버린 오늘 작품은 판매되지 않는다.
- 수용 기준:
  - AC-01: `Make(boat)`, `EndDay` → 정산 합계 9, 돈 28(= 20 − 1 + 9).
  - AC-02: `Make(plane)`, `EndDay` → 1일차 인기 plane, 합계 9, 돈 28.
  - AC-03: 1일차 `Make(plane)`(★3), boat ★2(AC: F-003 AC-03 입력), boat ★1(F-003 AC-04 입력), `EndDay` → 합계 9 + 6 + 3 = 18, 돈 35(= 20 − 3 + 18).
  - AC-04: 가격 계산은 CONTENT_SPECS 판매가 표의 30개 값(5작품 × 3등급 × 인기/일반)과 모두 일치한다.
  - AC-05: `EndDay` 후 오늘 작품 0개다. 작품 없이 `EndDay` → 합계 0, 돈 불변.
  - AC-06: 1일차 `Make(boat)` 후 `EndDay` → 1일차 가격 9로 판매(2일차 인기 boat 가격 13이 아님).
  - AC-07: 1일차 `Make(boat)`, `Waste(plane)`, `EndDay` → 총 판매액 9, 총 종이값 2.
- 범위 밖: 손님·주문, 재고 보관, 가격 협상, 판매 수량에 따른 가격 하락.

### F-006 엔딩 판정 · 결과 화면
- 목적: 무엇을 접었는지와 번 돈으로 런을 평가한다.
- 관련 규칙: R-014
- 기대 동작: 런 종료 시 (종료 사유, 최종 돈, 작품별·등급별 완성 수)만 사용해 우선순위 E-01 → E-05 순으로 첫 만족 엔딩 결정. 결과 화면에 엔딩 이름·문구와 기록(최종 돈, 작품별 완성 수·등급 분포, 실패 수, 총 판매액, 총 종이값)을 표시하고 "다시 시작"(`NewRun`)을 제공.
- 엣지 케이스: 여러 엔딩 동시 만족 → 우선순위가 높은 하나. 경계값은 "≤ 20", "≥ 15", "≥ 1000"(포함). 학 완성은 등급 무관. E-04는 5종 모두 ★3이 1개 이상(★2만 있는 작품이 있으면 불만족).
- 수용 기준 (판정 입력 조합 → 기대 엔딩; 판정은 이 입력만으로 테스트 가능해야 한다):
  - AC-01: 파산, 돈 0 → E-01.

### F-007 화면 · 조작 (프레젠테이션)
- 목적: Core 규칙을 단순 도형·텍스트 UI로 플레이 가능하게 보여 준다. 규칙 판단은 하지 않고 F-001~F-006 결과만 표시한다.
- 화면 구성:
  1. **작업대(기본 화면)**: 일차 `n/7`, 돈, 남은 시도 `k/5`, 오늘의 인기 작품, 작품 목록(5종: 이름, 단계 수, 종이값, 오늘 ★3 예상가, 잠김이면 해금 조건 문구 예: "종이배 3개 완성 시 (1/3)"), 오늘 완성 작품 목록, "하루 마치기" 버튼.
  2. **도안 미리보기**: 해금된 작품을 고르면 정답 순서 전체를 기호/화살표로 보여 준다. 횟수·비용 제한 없음. "접기 시작"(종이값 표시)과 "닫기". 잠긴 작품은 도안을 보여 주지 않는다.
  3. **접기 화면**: 종이(단색 정사각형), 진행 `i/N`, 맞힌 단계 기호, 실수 `m/3`, 힌트 수, 예상 등급, 동작 버튼 5개 + 힌트 + 포기. **남은 단계의 정답은 보이지 않는다**(힌트로 공개된 현재 단계만 예외).
  4. **완성/망침 알림**: 완성 시 작품 도형·등급(★), 망침 시 "종이를 망쳤다" 문구 후 작업대로 복귀.
  5. **정산 화면**: 오늘 판매한 작품별 가격, 합계, 정산 후 돈, 다음 날 인기 작품(7일차 제외). 확인 시 다음 날 또는 결과 화면.
  6. **결과 화면**: F-006 AC-11.
- 조작: GAME_RULES 표의 키(↑/W, ↓/S, ←/A, →/D, Space, H, Esc)와 같은 기능의 화면 버튼. 키와 버튼은 같은 명령이다.
- 엣지 케이스:
  - 거부된 명령은 사유별 안내 문구를 1개 표시한다(예: NotEnoughMoney → "돈이 부족합니다", NoAttemptsLeft → "오늘은 더 접을 수 없습니다", Locked → 해금 조건 문구). 상태는 바뀌지 않는다.
  - 접는 중에는 작업대의 작품 선택·하루 마치기가 동작하지 않는다.
  - 접기 화면이 아닐 때 방향키·Space 입력은 아무 효과가 없다.
  - Esc(포기)는 실수 방지를 위해 확인 단계를 1번 거친다(확인 전까지 상태 불변).
- 수용 기준:
  - AC-01: 게임 실행 직후 작업대에 "1/7", 돈 20, 시도 "5/5", 인기 작품 "종이비행기"가 표시된다.
  - AC-02: 작업대 작품 목록에 5종이 모두 보이고 frog·crane·dragon은 잠김 표시와 해금 조건 진행(예: "0/3")이 표시된다.
  - AC-03: 접기 화면에서 정답 키를 누를 때마다 진행 표시가 1씩 오르고, 오답 키는 실수 표시를 1 올린다(F-003과 같은 결과).
  - AC-04: 접기 화면에 남은 단계의 정답 기호가 표시되지 않는다(힌트로 공개된 현재 단계 제외).
  - AC-05: 화면 버튼과 대응 키는 같은 결과를 낸다(예: ↑ 키와 "위로 접기" 버튼 모두 `In(U)`).
  - AC-06: "하루 마치기" 후 정산 화면에 합계와 정산 후 돈이 F-005 결과와 일치하게 표시된다.
  - AC-07: 모든 그래픽은 코드로 만든 도형·텍스트이며 외부 이미지 에셋 없이 동작한다.
- 범위 밖: 접힘 애니메이션의 사실적 표현, 사운드, 설정 메뉴, 키 재배치, 다국어.
