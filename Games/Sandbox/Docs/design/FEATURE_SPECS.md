### F-001 점수 카운터 (연타 콤보)
- 목적: 입력 → 점수 → 콤보 배수의 최소 루프를 제공하고, 팀 파이프라인을 검증할 수 있는 작고 완전히 테스트 가능한 규칙을 정의한다.
- 관련 규칙: `GAME_RULES.md` R-001 ~ R-006
- 요구사항:
  - 규칙은 Unity 없이 테스트 가능해야 한다. 입력·상태 조회에 쓰이는 시각(초)은 **반드시 호출자가 명시적으로 전달**한다(R-001). 리셋은 시각을 받지 않는다(R-005).
  - 상태로 최소한 점수, 현재 콤보 수, 현재 배수를 조회할 수 있어야 한다.
  - Space 키와 마우스 왼쪽 클릭은 같은 "입력"이다. 리셋은 별도 동작이다(키 배정은 구현 측 결정, 예: R 키 또는 화면 버튼).
  - 화면에 점수, 콤보 수, 배수를 표시한다.
- 기대 동작:
  1. 시작 상태: 점수 0, 콤보 0, 배수 x1.
  2. 입력 시 R-003에 따라 콤보 갱신 후, 갱신된 콤보의 배수(1~4: x1, 5~9: x2, 10~19: x3, 20+: x4)로 `1 × 배수`점 가산.
  3. 직전 입력과 간격 1.0초 이하 → 콤보 +1, 1.0초 초과 → 콤보 1부터 다시.
  4. 조회 시각이 마지막 입력 후 1.0초를 넘으면 콤보 0, 배수 x1로 보고(점수 유지).
  5. 리셋(시각 인자 없음) → 점수 0, 콤보 0, 직전 입력 기록 삭제.
- 엣지 케이스:
  - 간격이 정확히 1.0초 → 콤보 유지.
  - 간격 0초(같은 프레임에 Space와 클릭) → 입력 2회, 콤보 유지.
  - 시각 역행 입력(`t < t_prev`) → 무시, 상태 불변.
  - 입력 시각이 NaN/±무한대 → 무시, 점수·콤보·`t_prev` 불변.
  - 조회 시각이 NaN/±무한대 → 예외 없이 마지막 유효 입력 시점의 상태(현재 점수, 마지막 입력 직후 콤보·배수)를 보고. 유효 입력이 없으면 점수 0, 콤보 0, 배수 1.
  - 조회 시각이 마지막 입력보다 이름(`now < t_prev`) → 마지막 입력 시점의 콤보·배수를 보고(만료 아님).
  - 리셋 직후 입력 → 시각과 무관하게 첫 입력(리셋 전보다 이른 시각도 허용).
  - 초기 상태에서 리셋 → 아무 변화 없음, 오류 없음.
  - 콤보 20 이후 계속 연타 → 배수 x4 고정.
  - 음수 시각도 유한값이면 유효(시계 기준점은 호출자 책임).
- 수용 기준 (테스트 가능한 문장):
  - 조회 시각 규약: 별도 명시가 없으면 상태는 **마지막 유효 입력 시각(now = t_prev)**에 조회한다. 유효 입력이 없는 상태(초기·리셋 직후)는 조회 시각과 무관하게 결과가 같다.
  - AC-01: 새로 만든 카운터는 점수 0, 콤보 0, 배수 1이다.
  - AC-02: t=0.0 입력 1회 후 점수 1, 콤보 1, 배수 1이다.
  - AC-03: t=0.0, 0.5, 1.0 입력 후 점수 3, 콤보 3이다.
  - AC-04: t=0.0, 1.0 입력 후 콤보 2이다(경계 1.0초는 유지).
  - AC-05: t=0.0, 1.001 입력 후 콤보 1, 점수 2이다(1.0초 초과는 끊김).
  - AC-06: 0.5초 간격으로 5회(t=0.0~2.0) 입력하면 5번째 입력에서 +2점, 총점 6, 배수 2이다.
  - AC-07: 0.5초 간격으로 10회 입력하면 총점 = 4×1 + 5×2 + 1×3 = 17, 배수 3이다.
  - AC-08: 0.5초 간격으로 20회 입력하면 총점 = 4×1 + 5×2 + 10×3 + 1×4 = 48, 배수 4이다.
  - AC-09: 0.5초 간격으로 25회 입력하면 총점 = 48 + 5×4 = 68, 배수 4이다(상한 유지).
  - AC-10: 콤보 7(배수 2) 상태에서 직전 입력 후 1.5초 뒤 입력하면 콤보 1, 그 입력은 +1점이다.
  - AC-11: t=0.0 입력 후 now=1.0 조회 시 콤보 1, now=1.5 조회 시 콤보 0·배수 1·점수 1이다.
  - AC-12: t=2.0 입력 후 t=1.0 입력은 무시되어 점수 1, 콤보 1이 유지되며, 이어서 t=2.5 입력 시 콤보 2가 된다.
  - AC-13: 같은 시각 t=0.0에 입력 2회 시 점수 2, 콤보 2이다.
  - AC-14: NaN 또는 무한대 시각 입력은 점수·콤보를 바꾸지 않는다.
  - AC-15: 점수 17·콤보 10 상태에서 리셋하면 점수 0, 콤보 0, 배수 1이다.
  - AC-16: t=5.0 입력 → 리셋 → t=1.0 입력 시 입력이 유효하며 점수 1, 콤보 1이다.
  - AC-17: 초기 상태에서 리셋해도 예외 없이 점수 0, 콤보 0이다.
  - AC-18: 동일한 입력 시각 열을 두 번 재생하면 두 결과(점수, 콤보)가 같다(결정적).
  - AC-19: t=2.0 입력 후 now=1.0 조회 시 점수 1, 콤보 1, 배수 1이다(마지막 입력보다 이른 조회는 만료 아님).
  - AC-20: 0.5초 간격으로 5회(t=0.0~2.0) 입력 후 now=NaN, now=+무한대, now=−무한대로 각각 조회하면 예외 없이 매번 점수 6, 콤보 5, 배수 2이다. 새로 만든 카운터를 now=NaN으로 조회하면 점수 0, 콤보 0, 배수 1이다.
  - AC-21: t=−1.0 입력 1회 후(now=−1.0 조회) 점수 1, 콤보 1, 배수 1이다(음수 유한 시각은 유효). 이어서 t=−0.5 입력 시 콤보 2, 점수 2이다.
  - AC-22: t=0.0, NaN, 0.5 순서로 입력하면 점수 2, 콤보 2이다. t=0.0, +무한대, 0.5 순서로 입력해도 점수 2, 콤보 2이다(무효 입력은 `t_prev`를 바꾸지 않음).
- 범위 밖: 최고 점수 저장, 사운드/연출, 제한 시간, 콤보 만료까지 남은 시간 게이지.
