# Sandbox 게임 규칙

> 담당: game-designer

## 기본 수치

| 이름 | 값 | 설명 |
|---|---|---|
| 기본 점수 (BASE_POINTS) | 1 | 입력 1회당 배수 적용 전 점수 |
| 콤보 유지 시간 (COMBO_WINDOW) | 1.0초 | 직전 입력과의 간격이 이 값 **이하**이면 콤보 유지 |
| 콤보 배수 단계 | 아래 표 | 콤보 수에 따라 결정 |
| 배수 상한 | x4 | 콤보 20 이상은 모두 x4 |

| 콤보 수 | 배수 |
|---|---|
| 1 ~ 4 | x1 |
| 5 ~ 9 | x2 |
| 10 ~ 19 | x3 |
| 20 이상 | x4 (상한) |

콤보 0(입력 없음·리셋 직후·콤보 만료)일 때 표시 배수는 x1이다.

## 규칙 목록

### R-001 시간은 외부에서 명시적으로 전달
- 설명: 모든 입력과 상태 조회에는 시각(초 단위 실수, 단조 증가하는 게임 시계 기준)이 인자로 주어진다. 규칙 로직은 스스로 현재 시각을 읽지 않는다.
- 기대 동작: 같은 입력 시각 열을 주면 언제 어디서 실행해도(Unity 없이도) 같은 결과가 나온다.
- 예외 상황: 시각이 NaN 또는 ±무한대이면 그 입력/조회는 무효 처리되고 상태는 변하지 않는다.

### R-002 입력 1회의 점수
- 설명: 유효한 입력 1회마다 먼저 콤보를 갱신(R-003)하고, 갱신된 콤보 수의 배수로 `BASE_POINTS × 배수`를 점수에 더한다.
- 기대 동작: 처음 입력 → 콤보 1, +1점. 5번째 연속 입력 → 콤보 5, +2점.
- 예외 상황: Space와 클릭은 동일한 입력이다. 같은 시각에 둘 다 들어오면 입력 2회로 각각 처리한다.

### R-003 콤보 유지/끊김
- 설명: 직전 유효 입력 시각을 `t_prev`, 이번 입력 시각을 `t`라 할 때
  - 직전 입력이 없으면(첫 입력·리셋 직후) 콤보 = 1.
  - `0 ≤ t − t_prev ≤ 1.0` 이면 콤보 = 이전 콤보 + 1.
  - `t − t_prev > 1.0` 이면 콤보 = 1 (끊기고 이번 입력이 새 콤보의 시작).
- 기대 동작: 경계값 1.0초 차이는 **유지**, 1.0초 초과는 **끊김**.
- 예외 상황: `t < t_prev`(시각 역행) 입력은 무효로 무시하며 점수·콤보·`t_prev` 모두 변하지 않는다.

### R-004 콤보 만료 표시
- 설명: 시각 `now`에 상태를 조회할 때, 직전 입력이 있고 `now − t_prev > 1.0`이면 콤보는 0, 배수는 x1로 보고한다. 점수는 그대로 유지된다.
- 기대 동작: 입력이 멈추면 1.0초 초과 시점부터 화면의 콤보가 0으로 바뀐다.
- 예외 상황: `now < t_prev`인 조회는 직전 입력 시점의 콤보를 그대로 보고한다(만료 아님).

### R-005 리셋
- 설명: 리셋 시 점수 0, 콤보 0, 직전 입력 기록 없음으로 되돌린다.
- 기대 동작: 리셋 다음 입력은 시각과 무관하게 "첫 입력"으로 처리된다(콤보 1, +1점). 리셋 이전 입력보다 이른 시각의 입력도 유효하다.
- 예외 상황: 이미 초기 상태에서 리셋해도 오류 없이 초기 상태를 유지한다.

### R-006 점수 범위
- 설명: 점수는 0 이상의 정수이며 감소하지 않는다(리셋 제외). 상한은 두지 않는다(입력당 최대 +4점이므로 정상 플레이로 정수 범위를 넘지 않는다고 가정).
